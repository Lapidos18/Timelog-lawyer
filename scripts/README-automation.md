# Ставки, документы и напоминания (032–035)

Это три согласованных пользователем изменения в существующих разделах. Новых вкладок нет. Перед публикацией вручную выполнить все четыре миграции одной транзакцией. Существующие часы, ставки, начисления, платежи не пересчитываются.

## Ставки

В редактировании дела расположен блок «Правила ставок». Каждое правило задаёт итоговую почасовую ставку к начислению, дату начала/окончания, при необходимости вид работы и исполнителя, основание из соглашения. Приоритет: вид работы и исполнитель, вид работы, исполнитель, общее правило. Для одинаковых условий пересекающиеся периоды запрещены базой. Причина и история сохраняются.

В новой записи обоих видов журнала правило применяется при смене дела, даты, вида работы или исполнителя. Дополнительная надбавка НДФЛ не применяется к правилу автоматически: в правиле уже итоговая договорная ставка. Пользователь может изменить ставку вручную; отклонение показано предупреждением. Изменение описания не сбрасывает вручную введённую ставку. Редактирование существующей записи сохраняет её ставку. При ошибке загрузки правил новая запись не сохраняется до успешной проверки. Без подходящего правила действует прежняя ставка дела/профиля.

Правила не создаются из прошлых записей автоматически: среди них могут быть выезды, особые условия и исправления. Новые условия нужно внести в карточке дела. Абонплата и фиксированные этапы по-прежнему учитываются существующими настройками и начислениями; почасовые правила не превращают бюджет дела в выставленную сумму.

## Акты из начислений

Форма акта получает услуги и расходы одним запросом. Услуги: оплачиваемое время для почасового дела, абонплата за месяцы, ручные начисления/фиксированные этапы и уменьшения стоимости. В абонентском деле часы повторно в стоимость услуг не включаются. Расходы берутся из записей выбранного дела/периода и сохраняются отдельно; их сумма в форме доступна только для чтения. Ранее возмещённый расход можно отразить в первом акте, но повторно выставить в другом действующем акте нельзя.

Сформированный документ содержит обычную таблицу времени при наличии часов и отдельную таблицу начислений/уменьшений без вымышленных часов и ставок. Возмещение расходов не включается в стоимость услуг. Суммы сверяются с сохранёнными строками при выпуске, полная версия Word/HTML/CSS фиксируется прежним механизмом. Для нулевой/отрицательной суммы услуг выпуск обычного положительного акта недоступен — нужен разбор корректировки.

База закрепляет каждую работу, месячную абонплату, начисление и расход за выпущенным актом. Другая действующая версия не может включить их повторно. Стоимость предъявленного источника защищена от изменения. При исправлении исходник сохраняется, связи освобождаются, создаётся новый черновик. Изменение абонплаты, которое переписало бы уже выставленные месяцы, блокируется; изменение условий требует отдельной подготовки, а не переписывания прошлого.

Если сохранились прежние черновики, пересобрать их из начислений перед выпуском. Миграция останавливается при действующих выпущенных актах с суммой расходов без расшифровки: нужно сначала сопоставить расходы, а не приписывать их автоматически. Перед подготовкой обновления в рабочей базе актов не было.

## Напоминания

Сохраняется существующее утреннее расписание. Обработчик keep-alive дневного расписания дополнительно повторяет только сегодняшние неудавшиеся части, содержание которых ещё соответствует текущим незавершённым событиям. Публичный вызов keep-alive не запускает отправку: для этого нужен секрет расписания. Ручной запуск /api/notify требует входа адвоката.

Очередь хранится в базе, часть имеет стабильный идентификатор по дню, содержимому и номеру. Подтверждённые части не отправляются заново; смена содержания создаёт новый пакет. Длинный Unicode-текст разделяется с запасом к лимиту Telegram. При подтверждённой временной ошибке возможны до трёх попыток; при ограничении Telegram учитывается retry_after, включая общую паузу остальных частей. Вызов ограничен по времени; оставшиеся части видны как ожидающие.

Сетевой обрыв, неверный ответ или прерванная отправка не считаются подтверждённой доставкой и не повторяются молча: Telegram не предоставляет ключ идемпотентности sendMessage. В интерфейсе предлагается проверить чат и явно разрешить повтор с предупреждением о возможном дубле. После исчерпания попыток подтверждённого отказа доступен ручной повтор; пауза Telegram не обходится. Статус приёма не означает прочтение.

В разделе сроков показаны последние проверки, части, результаты и время попыток. Без новой проверки отображается её последняя дата. Ошибки и отсутствие настроек видны в интерфейсе; ключи бота и авторизации в сообщения об ошибках не попадают. Независимый внешний монитор запуска расписания не настраивался, новый платный тариф не подключался.

Протокол и ограничения: [Telegram Bot API](https://core.telegram.org/bots/api#sendmessage), [время выполнения функций Vercel](https://vercel.com/docs/functions/configuring-functions/duration). Плановое время зависит от запуска заданий хостингом, поэтому точность до минуты не гарантируется.

## Копии и проверка

Копия содержит 23 таблицы; старые копии с 20 таблицами продолжают проверяться и восстанавливаться. При восстановлении сначала загружаются акты, затем связи с начислениями; отложенные внешние ключи проверяются до включения пользовательских триггеров. Новые таблицы не содержат ключей Telegram.

Перед push обязательна полная команда npm run build: Vitest, финансовые сценарии в отдельном PostgreSQL, типы, страницы. Для Telegram тесты используют подставной ответ; настоящие сообщения при разработке не отправляются. Фактический канал после публикации проверяет обычная кнопка отправки/расписание с записью результата.
