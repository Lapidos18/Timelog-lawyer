# Автоматическая резервная копия на этот компьютер

Скрипт `backup-local.mjs` выгружает все таблицы базы в JSON-файл на диск.
Формат тот же, что у кнопки «Скачать резервную копию» в приложении, —
файлы взаимозаменяемы.

**Данные никуда не отправляются:** только с сервера Supabase на ваш диск.
Никаких почтовых сервисов и сторонних хранилищ.

---

## Шаг 1. Один раз добавить ключ доступа

Автоматика работает без входа по паролю, поэтому ей нужен служебный ключ.

1. Откройте панель Supabase → **Project Settings → API Keys**
2. Скопируйте ключ **`service_role`** (не `anon`)
3. Откройте файл `.env.local` в корне проекта и допишите строку:

```
SUPABASE_SERVICE_ROLE_KEY=сюда_вставить_ключ
```

`.env.local` уже указан в `.gitignore` — в репозиторий он не попадёт.

> Этот ключ даёт полный доступ к базе в обход проверки прав.
> Не пересылайте его в мессенджерах и не вставляйте в переписку.
> Если он всё же где-то засветился — его можно перевыпустить в той же
> панели Supabase, старый сразу перестанет работать.

## Шаг 2. Проверить вручную

```
npm run backup
```

Должен вывести список таблиц с галочками и путь к сохранённому файлу.

## Шаг 3. Поставить на расписание

**Уже сделано 20.09.2026.** В Планировщике заданий Windows есть задание
**«Timelog backup»**: ежедневно в 20:00, запускает `scripts\backup-task.cmd`.
Отмечено «запускать при первой возможности, если запуск пропущен», поэтому
копия сделается и в день, когда компьютер включили позже. От батареи тоже
запускается.

Обёртка `backup-task.cmd` нужна, чтобы задание стартовало из папки проекта
(иначе не найдётся `.env.local`) и писало журнал. Путь внутри неё не задан
жёстко — папка вычисляется от самого файла.

Если задание понадобится пересоздать, в PowerShell:

```powershell
$action  = New-ScheduledTaskAction -Execute "C:\Users\User\Documents\Timelog-lawyer\scripts\backup-task.cmd"
$trigger = New-ScheduledTaskTrigger -Daily -At 20:00
$settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -AllowStartIfOnBatteries -DontStopIfGoingOnBatteries -ExecutionTimeLimit (New-TimeSpan -Minutes 10)
Register-ScheduledTask -TaskName "Timelog backup" -Action $action -Trigger $trigger -Settings $settings -Force
```

## Вторая копия: Google Диск или внешний диск

Копии на том же компьютере спасают от ошибки в данных, но не от пропажи
самого компьютера. Поэтому после сохранения файл копируется ещё раз — туда,
где он переживёт компьютер.

**Google Диск.** Настраивать ничего не нужно: поставьте
[Google Диск для компьютера](https://www.google.com/drive/download/), войдите
в свой аккаунт — он подключит диск с папкой «Мой диск». Скрипт сам её найдёт
и будет складывать копии в «Мой диск\Timelog-backups». Там действует та же
ротация: последние 30 копий.

Если Google Диск не установлен или не запущен, скрипт про это пишет и
спокойно продолжает работу — основная копия уже сохранена, задание не падает.

**Другая папка (внешний диск, вторая облачная папка).** Задаётся
`TIMELOG_BACKUP_MIRROR` в `.env.local`; несколько папок — через точку с
запятой:

```
TIMELOG_BACKUP_MIRROR=F:\Timelog-backups
```

Указанная вручную папка **не отменяет** найденный Google Диск: внешний диск и
облако — две разные страховки, копии кладутся в обе.

> В файле копии лежат ФИО доверителей, ИНН, телефоны и адреса. Папку
> «Timelog-backups» на Google Диске не нужно никому открывать по ссылке.

## Как проверить, что копии делаются

Открыть папку `C:\Users\User\Documents\Timelog-backups` и посмотреть на даты
файлов. Рядом лежит `backup-log.txt` — журнал запусков: дата, список таблиц
и путь сохранённого файла. Журнал в кодировке UTF-8, открывается Блокнотом.

В самом Планировщике у задания «Timelog backup» виден столбец «Результат
последнего запуска»: `0` — копия сделана.

---

## Где лежат копии

По умолчанию: `C:\Users\User\Documents\Timelog-backups`
(намеренно вне папки проекта, чтобы данные доверителей не могли попасть в git).

Хранятся **последние 30** копий, старые удаляются сами.

Изменить можно переменными окружения:
- `TIMELOG_BACKUP_DIR` — другая папка
- `TIMELOG_BACKUP_KEEP` — сколько копий хранить

## Если выгрузка сорвалась

Скрипт **не сохраняет неполный файл**: если хотя бы одна таблица не
выгрузилась, копия не записывается, а прежние остаются нетронутыми.
В Планировщике такая задача будет отмечена как завершившаяся с ошибкой.

## Как восстановить данные

Файл — обычный JSON со всеми таблицами. Восстановление делается загрузкой
данных обратно в Supabase; разово это проще сделать через SQL Editor или
попросить разработчика. Главное — что сами данные у вас на руках.
