# Расчёты и закрытие месяца

Миграции 024–029 включают распределения платежей, защищённые версии документов, закрытие месяца, историю времени и проверяемое резервирование. Их необходимо выполнить вручную в Supabase SQL Editor перед публикацией нового интерфейса.

## Платёж по нескольким заданиям

В разделе «Платежи и акты сверки» у поступления нажать «Распределить». Добавить задания; по каждому указать вознаграждение и возмещение. При наличии акта выбрать его, чтобы учитывались частичная оплата и остаток именно этого документа. Без акта сумма учитывается по заданию; без распределения — по доверителю в целом. Одно банковское поступление никогда не превращается в несколько доходов.

Возмещения в распределении должны совпадать с расходами, уже отмеченными в платеже. Для изменения состава возмещений сначала убрать все части распределения и сохранить, затем изменить платёж и распределить его заново. Связи с расходами и исходный платёж при снятии распределения сохраняются.

## Остатки

«Расшифровка расчётов» показывает начальный остаток, работы, начисления, расходы, уменьшения и оплаты. Положительный конечный остаток — долг доверителя, отрицательный — аванс. Нераспределённые суммы видны отдельно и не уменьшают долг произвольно выбранного задания.

## Документы

Выпуск акта фиксирует строки, реквизиты и печатное содержание. Изменение карточки доверителя не изменяет сохранённый акт. Исправление создаётся отдельным черновиком с причиной; оригинал сохраняется, а привязанные оплаты переходят на исправленную версию. Повторно выставить запись времени в двух действующих выпущенных актах нельзя.

При выпуске сохраняются точные байты Word-файла. Повторное скачивание выпущенного акта берёт этот файл, не собирая его заново текущей версией шаблона. Для печати/PDF сохраняются исходные HTML и CSS документа. Скан с подписями сторон не создаётся автоматически.

Платёж меньше суммы акта оставляет остаток; платёж больше суммы показывает переплату. Развилка «без записи платежа» сохранена как явное ручное подтверждение, которое не создаёт банковское поступление. Такой акт отмечен отдельно до привязки реального платежа.

## Удалённые экраны

Вкладки закрытия месяца и расшифровки расчётов удалены по указанию пользователя. Не возвращать и не переносить их функции без согласования. Исторические таблицы и ограничения базы сохранены для совместимости копий.

## Импорт и автоматическое распределение (030–031)

Перед публикацией выполнить обе миграции вручную в SQL Editor. Они создают функции, но не перераспределяют прежние платежи.

При новом платеже без явно выбранного задания автоподбор включён по умолчанию. Основание — остатки начислений и предъявленных расходов на дату оплаты, а не наличие подписанного акта. Будущие начисления не включаются; все уже распределённые оплаты учитываются. Только единственный набор полностью погашаемых заданий с точным совпадением до копейки распределяется автоматически. Вознаграждение и расходы остаются раздельными; подтверждённые компенсации связываются с исходным платежом. При другом нераспределённом платеже доверителя, нескольких вариантах, несовпадении или более 16 подходящих заданиях требуется ручное распределение. Явный выбор задания и отключение автоподбора сохраняют ручной режим. Редактирование платежей не запускает перераспределение заново.

В выписке автоподбор также включён, но его можно отключить и выбрать задание вручную. Повтор банковской операции защищён транзакцией и отпечатком счёта, даты, суммы, номера документа, плательщика и назначения. Имя файла и позиция строки не влияют на отпечаток. Результат сохраняется в уже резервируемой таблице financial_operations; обе таблицы поступлений проверяются при предварительном просмотре. Совпадение только даты/суммы считается возможным дублем и требует проверки пользователя. Полностью одинаковые строки одного файла не импортируются дважды; при отсутствии различающего банковского реквизита нужна ручная сверка.

Успешные строки блокируются, ошибки остаются отмеченными для повторной отправки. Закрывать окно после частичного успеха не требуется. Повтор после потери ответа сервера возвращает прежнее поступление; удалённое ранее поступление не восстанавливается молча.

## Автоматические проверки

`npm run build` запускает Vitest и `scripts/test-finance-db.cjs`, затем полную сборку Next.js. PostgreSQL-тест работает только в памяти с вымышленными данными, не читает `.env.local` и не обращается к рабочей базе.
